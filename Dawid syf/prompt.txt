Pracuję nad projektem konkursowym „AI Control Layer”.

Celem projektu jest stworzenie lekkiej, elastycznej warstwy bezpieczeństwa działającej jako gateway / proxy / middleware / SDK wrapper pomiędzy aplikacjami, agentami AI, MCP, LLM-ami i narzędziami.

Jednym z wymaganych elementów są:

**Controls / Guardrails**

1. Deterministic (Non-AI): np. pattern matching (wykrywanie PII lub secrets), sprawdzanie uwierzytelnienia i wymagań dostępu itp.

Chcę teraz przygotować **bardzo dokładny research dotyczący Deterministic / Non-AI Security Controls** dla LLM, Agentic AI, AI Agents, MCP i systemów generatywnej AI.

# 5. Co MUSI znaleźć się w każdym case

Dla każdego przypadku odpowiedz na pytania:

### Problem

Co chronimy?

### Threat / Attack

Przed czym dokładnie się bronimy?

### Attack mechanism

Jak działa atak?

### Deterministic detection

Jak wykryć go bez AI?

### Enforcement point

W którym miejscu AI Control Layer należy zastosować kontrolę?

Np.:

```text
Request
↓
Authentication
↓
Normalization
↓
Policy resolution
↓
Deterministic control
↓
LLM / Agent / MCP
↓
Output control
↓
Response
```

### Action

Co zrobić po wykryciu?

* ALLOW
* REDACT
* BLOCK
* RATE_LIMIT
* QUARANTINE
* REVIEW

### Bypass

Jak można ominąć tę kontrolę?

To jest bardzo ważne.

### Limitations

Jakie są false positives / false negatives?

### AI boundary

Co możemy zrobić deterministic, a czego nie?

### Implementation

Jak można to zaimplementować w naszym projekcie?
